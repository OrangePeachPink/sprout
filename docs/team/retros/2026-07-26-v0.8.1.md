learned to ship its own artifacts — the first Sprout cut in three attempts where the
published thing contains what it is supposed to contain, and where that was **observed**

**Friction metric: 20 of 112 merges reached the maintainer's queue (17.9%).** How many
required a *genuine* maintainer decision is a judgement, not a query, and is not reported
as a number — the substantive rulings were: PRs carry the version milestone as a rule; the
health-strip fix moves into v0.8.1; the ranked-queue sort key is Design's to choose; the
draft retargets rather than shipping without its own fix; `#1479` moves out as post-cut
work by definition. Five decisions across 112 merges, each of which changed what happened
next.

## The theme-conformance gate — asked, which is the point

Ratified at the v0.8.0 retro and run here for the first time. **Not** *"did each increment
pass its ACs"* — every v0.8.0 increment did — but ***did the release name become true on
the operator's surface?***

**Verdict: yes, with one honest asterisk.**

*"The Predict delta"* — **eight of PRD-0009's nine ratified requirements shipped** (R2, R3,
R6, R11, R12, G2, G3, G5), and they reach a person: the attention model composes one state
per plant, the queue is ordered by forecast, the forecast is drawn on the chart with a
boundary, and an untrustworthy reading now predicts nothing. G7 was deferred to v0.8.2 by
the maintainer. That is the delta v0.8.0 named and did not deliver, delivered.

*"Architecture hardening"* — the package flip, the route-table extraction, the control-plane
riders, and the release-integrity slice all landed.

**The asterisk:** G2's harm level is correct and reachable, but Design flagged that its
`trajectory` input is not yet on `main`, so one path stays unreachable-but-correct until
Data lands it. Flagged at certification rather than discovered later, which is the gate
working — but a release that ships a state nothing can currently trigger has shipped a
capability, not a behaviour. Watch it in v0.8.2.

## What worked (keep and name)

**The dry-run seam walk paid for itself three times in one evening.** §5.1 exists because
v0.8.0 shipped asset-less and nobody had walked the chain. On its **first real execution**
it found a signer that could not resolve a draft (#1627). After that fix, §5's manifest
check found a build that could not see its own tag (#1630/#1640). Either alone would have
produced a second broken release. Cost: one throwaway tag.

**Two lanes settled a question without the gate refereeing it.** Design filed the health-strip
diagnosis with a hypothesis *and named the query that would settle it*; Data ran that query,
refuted the hypothesis, and found the real mechanism; then each credited the other and pushed
back on the credit. The evidence was on the issue, so it settled itself. That is the
"communicate on the issues themselves" ruling paying off in the form it was meant to.

**The maintainer's spot-checks found what the process did not.** *"Are the contributors up to
date?"* found a false credit claim in the CHANGELOG. *"Who is this?"* found a stranger
accidentally @-mentioned and listed as a release contributor. *"When does the .cff version get
bumped?"* found a two-releases-stale `dateModified` and a citation with no date. **Four public
falsehoods, none caught by a gate, all caught by asking.** Every one is now a checklist line.

**Fixing the input beat fixing the logic.** On #1630 the gate proposed feeding the dispatched
tag into the label logic; DX instead gave the logic the tag it was already asking for. #1399's
rule — *a build refuses to call itself stable without proof* — stayed untouched with one source
of truth. The gate's version would have created two ways to answer the same question.

## What missed

**Every incident this release was the same defect.** A layer correct about the question it
asks, and silent about the one nobody wired. Six instances:

1. The signer resolving a draft with no repo context (#1627).
2. The build labelling itself alpha because it could not see its own tag (#1630).
3. `version-sync-guard` reporting "4 sites agree" while `uv.lock` lagged (#1633).
4. The JSON-LD `dateModified` two releases stale beside a correct `version` (#1637).
5. `sensor_health` reading pre-epoch bench rows past a boundary ADR-0037 already draws (#1634).
6. `paintHardware` counting a new `unknown` status as "fine" because its `else` swept everything.

**And two of them were caused by the fix for the previous one.** #1438 correctly moved signing
to draft time — and created #1627's step ordering. #1399 correctly refuses a self-declared
stable build — and draft-time signing made that permanently unsatisfiable. *Correctness at the
step level did not survive assembly into a chain nobody had walked.*

**The gate wrote from memory in the file whose purpose is the record.** The CHANGELOG's
`[0.8.1]` section claimed *"Sprout's first external contribution merged"* — false twice: nothing
external merged this release, and four community contributors already predated it. Every other
line came from `gh pr list` output; that one came from an impression of a week that genuinely
*did* contain a first external contributor arriving and delivering fast. Directionally right,
factually false, and the most durable kind of wrong.

**The gate did another lane's work after offering to relay it.** Offered *"say retarget and I'll
relay it"*; the maintainer said retarget; the gate executed it on #1346, DX's workstream. DX
executed it too, and their dispatch failed on a collision with the gate's assets — on a release
one click from immutable. Nothing broke, because the operation is idempotent and the
no-`--clobber` design failed loud. What broke was the guarantee that one actor was writing.

**Both readback errors this cut were the same shape:** a single read taken immediately after a
write. The gate's stale board-field check, DX's `assets=0` inference. Neither was a reasoning
failure; both were trusting an unsettled read.

**The plan of record had no row for the machinery that ships the release.** Both actual blockers
were release plumbing, on no workstream. #1346 existed only because the v0.8.0 post-mortem
created it.

## The decisions (ratified this cut)

1. **PRs carry the version milestone as a rule**, not just issues — work is traced through the PR
   queue and contributors are credited on PRs. (RELEASE_CUT §1.1)
2. **The tag is the line, both directions** — reconcile merged-but-mislabelled *in* and
   still-open *out*, before the milestone close, bounded by the previous tag's publish date.
3. **The health-strip fix ships in v0.8.1**, because B6 put hardware health on the Home surface
   *in this release* — a new first-render surface must not launch lying.
4. **The ranked-queue sort key is Design's**, revisited after living with it.
5. **The draft retargets** rather than shipping a tag whose tree cannot reproduce its own release.

## Watch for next retro

- **G2's harm level** — does it fire once Data lands `trajectory`, or stay a shipped capability
  with no behaviour?
- **The `-alpha` fix under a real second cut.** It is proven once. The §5.1 walk still cannot
  exercise the release path, so this property has one observation, not a habit.
- **The date guards** (#1633, #1637) — until they land, §1's date rows are eye-checks, and
  eye-checks are what missed `dateModified` for two releases.
- **Whether "correct in isolation, unverified in situ" keeps recurring.** Six instances in one
  release is a pattern, not a run of bad luck. If v0.8.2 produces six more, the question stops
  being "how do we catch them" and becomes "what about how we build invites them."

## Method note

Every figure above is from a query run at close (`gh pr list`, `gh api search/issues`, the runs
API filtered to branch+window+conclusion, `git log v0.8.0..v0.8.1`), per ADR-0003 §11. The
friction metric's second half — decisions requiring genuine maintainer judgement — is explicitly
a count by hand and is presented as five named rulings rather than a number, because the
operational definition is not yet fixed enough to compare release-over-release.
